title: Windows

Lific runs natively on Windows. The server, web UI, CLI, REST API, MCP server and automatic backups all work, SQLite is compiled into the binary, and `lific login` keeps its tokens in the Windows Credential Manager. The published Windows binary targets `x86_64-pc-windows-msvc`.

One thing is missing: Lific registers no Windows service. `lific service install`, `status`, `restart`, `stop` and `uninstall` all fail with "no supported service manager found", because those commands drive systemd or launchd. Keep the server running with Task Scheduler or a terminal window, both covered below.

If you would rather have the service integration, run the Linux binary under WSL 2. That path is at the end of this page.

## Install

Download `lific-windows-x86_64.exe` and `sha256sums.txt` from the [releases page](https://github.com/VoidNullable/lific/releases), then verify the download in PowerShell:

```powershell
$expected = (Select-String -Path sha256sums.txt -Pattern 'lific-windows-x86_64\.exe').Line.Split(' ')[0]
$actual   = (Get-FileHash lific-windows-x86_64.exe -Algorithm SHA256).Hash
if ($actual -ieq $expected) { "checksum ok" } else { "checksum MISMATCH" }
```

Rename it to `lific.exe`, put it in a directory on your `PATH`, and check it:

```powershell
lific --version
```

### Or install with Cargo

Cargo builds Lific from source on your machine, which is also the way to try an architecture the releases do not cover.

Install rustup from [rustup.rs](https://rustup.rs) and keep the default MSVC host toolchain (`stable-x86_64-pc-windows-msvc`), which needs the Visual Studio C++ build tools. The rustup installer offers to install them. If you skip that, install the "Desktop development with C++" workload from the [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) installer.

```powershell
cargo install lific
```

Lific needs Rust 1.88 or later. The crates.io package carries the prebuilt web UI, so Bun is not involved. Compilation takes several minutes and the binary lands in `%USERPROFILE%\.cargo\bin\lific.exe`, which rustup already put on your `PATH`.

## Create the instance

```powershell
lific init --no-service
```

`--no-service` is the Windows form. Plain `lific init` does everything else correctly, then warns "couldn't install a background service: no supported service manager found" and tells you to run `lific start` yourself. Passing the flag skips that step and the warning with it.

`init` asks for your name and how people should sign in. Login-free mode writes `[auth] required = false`, pins `[server] host` to `127.0.0.1`, turns on browser auto-login and creates a passwordless administrator. Password mode leaves the bind host alone, keeps authentication on, and asks for the administrator's password. [Quickstart](/docs/quickstart#create-the-instance) describes the choice, and `--auth-mode`, `--name` and `--password` make it non-interactive.

On Windows, `init` writes both files under your roaming profile:

| File | Path |
| --- | --- |
| Configuration | `%APPDATA%\lific\lific.toml` |
| Database | `%APPDATA%\lific\lific.db` |

Attachments and automatic backups go next to the database, in `%APPDATA%\lific\attachments` and `%APPDATA%\lific\backups`. Add `--here` to `init` to keep the whole instance in the current directory instead, as `.\lific.toml` and `.\lific.db`.

## Run the server

```powershell
lific start
```

The default port is `3456`. Open `http://127.0.0.1:3456` and sign in as the administrator `init` created. Ctrl+C stops the server.

The built-in default bind host is `0.0.0.0`, which accepts connections from your local network, so Windows Defender Firewall asks for permission the first time. Login-free initialization already wrote `127.0.0.1`. Otherwise set it yourself if this instance is only for you:

```toml
[server]
host = "127.0.0.1"
port = 3456
```

From here the rest of the [Quickstart](/docs/quickstart) applies unchanged: connect your AI tools with `lific connect`, then create a project and an issue.

## Keep it running with Task Scheduler

A scheduled task can start the server when you sign in to Windows:

```powershell
$action   = New-ScheduledTaskAction -Execute (Get-Command lific).Source -Argument "start"
$trigger  = New-ScheduledTaskTrigger -AtLogOn -User $env:USERNAME
$settings = New-ScheduledTaskSettingsSet -ExecutionTimeLimit ([TimeSpan]::Zero) `
              -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries
Register-ScheduledTask -TaskName "Lific" -Action $action -Trigger $trigger -Settings $settings
```

The settings line matters. Without it, Task Scheduler stops a task after three days, and on a laptop it will not start the task on battery power and stops it when you unplug.

The task finds the configuration in `%APPDATA%\lific` the same way `lific start` does in a terminal. If you created the instance with `--here`, change the argument to `"--config C:\path\to\lific.toml start"`.

Start it now with `Start-ScheduledTask -TaskName "Lific"`, and remove it with `Unregister-ScheduledTask -TaskName "Lific"`. If PowerShell reports that access is denied when you register it, run PowerShell as administrator.

A task created this way runs in your session and shows a console window; closing that window stops the server. To run it without a window, open Task Scheduler, edit the task, and select "Run whether user is logged on or not". Saving that option asks for your account password.

Task Scheduler does not watch the process the way systemd does. If the server exits, it stays down until you next sign in or start the task yourself. If that matters, use WSL 2.

## WSL 2

WSL 2 runs the Linux release binary, which means `lific init` can install a systemd user service that restarts on failure.

Install a distribution if you do not have one:

```powershell
wsl --install
```

Inside the distribution, confirm systemd is on. `/etc/wsl.conf` must contain:

```ini
[boot]
systemd=true
```

Recent Ubuntu WSL images ship with it enabled. If you add it by hand, run `wsl --shutdown` from Windows and reopen the distribution.

Then follow [Installation](/docs/installation) for Linux: download `lific-linux-x86_64`, verify it, make it executable, put it on your `PATH`, and run `lific init`. The service step works because systemd is there.

WSL forwards localhost, so `http://localhost:3456` answers from a Windows browser while WSL is running. That caveat is the real one: WSL shuts its virtual machine down once no sessions or processes remain, and the server goes with it. Keep a WSL terminal open, or start the distribution before you need the tracker.

## Build from source natively

A native source build needs Rust 1.88 or later, the Visual Studio C++ build tools and [Bun](https://bun.sh). Build the web UI first, because `build.rs` refuses a release build when `web\dist\index.html` is missing:

```powershell
git clone https://github.com/VoidNullable/lific
cd lific
cd web; bun install; bun run build; cd ..
cargo build --release
```

The binary is written to `target\release\lific.exe`.

The published Windows artifact is built differently: it is cross-compiled on Linux for the same MSVC target through the repository's `release-windows-msvc` devenv profile, then downloaded onto a Windows runner that checks its checksum and exercises its startup, database, API and embedded frontend before the release is published. Native Windows Clippy and `cargo test --all-targets` run as their own CI job on every push.
