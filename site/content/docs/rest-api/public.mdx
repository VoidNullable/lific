---
title: Reading without a credential
description: Which ordinary API routes answer a request with no credential for a published project, what they leave out, and the limits that protect the instance from them.
---

When a lead publishes a project (`PUT /api/projects/{id}` with `"is_public": true`), anyone can read it through the ordinary API, with no account and no credential. There is no separate prefix: the routes, JSON shapes and paging headers are the ones a member uses. [Public projects](/docs/public-projects) covers what publishing exposes and how to review a project first.

A signed-in account or API key with no role in a published project reads it through the same routes, and every write it sends gets `403`.

## Routes

These answer `GET` with no credential. Every other route, and every other method, still answers `401`.

| Route | Returns |
| --- | --- |
| `/api/projects` | The published projects. |
| `/api/projects/{id}` | One published project. |
| `/api/projects/{id}/index`, `/changes` | [Delta sync](/docs/rest-api/sync). The cursor counts only this project's writes. |
| `/api/projects/{id}/board`, `/issue-counts`, `/relations`, `/insights` | The board, counts, dependency graph and insights. |
| `/api/projects/{id}/activity`, `/activity/actors` | The project's activity. |
| `/api/projects/{id}/my-role` | `{"enforced": true, "role": null}`. |
| `/api/projects/{id}/attachments` | The project's files. |
| `/api/issues`, `/api/issues/{id}`, `/api/issues/resolve/{identifier}` | Issues, limited to published projects when no `project_id` is given. |
| `/api/issues/{id}/comments`, `/activity`, `/waits` | Comments, history and waits. |
| `/api/pages`, `/api/pages/{id}`, `/api/pages/resolve/{identifier}` | Pages in published projects. Workspace pages are never included. |
| `/api/pages/{id}/comments`, `/activity` | Comments and history. |
| `/api/plans`, `/api/plans/{id}`, `/api/plans/resolve/{identifier}`, `/api/plans/{id}/activity` | Plans and their history. |
| `/api/modules`, `/api/modules/{id}`, `/api/labels`, `/api/folders` | The project's structure. |
| `/api/attachments?entity_type=&entity_id=` | Files on an issue, page or comment. |
| `/api/attachments/{id}`, `/thumbnail`, `/preview`, `/links` | A file, its thumbnail or preview, and where it is used. |
| `/api/search` | Search across published projects. |
| `/api/clock` | The server's calendar day and UTC offset. |

```bash
curl "$LIFIC/api/issues/resolve/APP-12"
```

The realtime socket at `/api/events/ws` also accepts a connection with no session cookie. It carries events for published projects only.

## What it leaves out

- Email addresses, API keys and session tokens never appear in a response.
- A plan step or anchor that points to an issue in a project the caller cannot read has no issue identifier or status.
- A relation to an issue in a project the caller cannot read is left out.
- Member lists, mention candidates, saved views, repository bindings, exports, archives, accounts and instance settings answer `401`.

## One answer for "no"

To a request with no credential, a project that is not published, a project that does not exist, a project unpublished a moment ago, an item in the trash and anything inside a private project all answer the same JSON `404`, `{"error": "not found"}`. Unpublishing takes effect on the next request.

Every response to a request with no credential, errors included, carries `Cache-Control: no-store`, `nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` and `Cross-Origin-Resource-Policy: same-origin`. A file download also carries `Content-Security-Policy: default-src 'none'; sandbox`, is streamed without byte ranges, and opens in the browser only when it is a plain image or media file.

## Limits

These requests carry no credential, so they are bounded to keep anonymous traffic from crowding out signed-in users:

| Limit | Value | When exceeded |
| --- | --- | --- |
| Requests per client address | 240 per minute | `429`, `Retry-After: 30` |
| Requests in progress, whole instance | 4 | `503`, `Retry-After: 2` |
| Attachment downloads in progress | 4 | `503`, `Retry-After: 2` |
| Thumbnail or preview being generated | 1 at a time | `503`, `Retry-After: 2` |
| Largest file a thumbnail or preview is generated from | 32 MiB | `404`. A thumbnail made earlier is still served. |
| Download | Ends after 15 seconds without progress, or 5 minutes in total | The connection is closed. |
| Realtime connections, whole instance | 64 | `429` |

Behind a reverse proxy, set [`trusted_proxies`](/docs/configuration#server) so the per-address limit sees visitors rather than the proxy. A request from a trusted proxy whose client-identity headers fail to verify is `503`.

## The retired `/public/api`

Lific 2.x served published projects on separate routes under `/public/api/projects/{project}`. They are gone in 3.0 and answer `404`. Point a client at the routes above and look projects up by id, or by identifier through `/api/issues/resolve/{identifier}` and the other `resolve` routes. Old `/public/{project}/...` page links in a browser redirect to `/{project}/...`.
