People write most issues here. Agents pick them up, do the work and close them. Treat each issue as the request: do what it asks, and ask when it is unclear.

## Picking up work
- Take open issues with no open blocker, highest priority first. Skip issues marked for a person.
- Set the issue active when you start and back to todo if you stop unfinished.
- If an issue is unclear, or holds changes that could each be completed and verified on their own, comment with your question or a proposed split and wait. Do not rewrite its description or scope.

## Finishing
- Close as done when the change is committed and does what the issue asked. Leave a closing comment: what changed, how you checked it, anything left out.
- If you cannot finish, leave it in todo with a comment saying where you stopped and why.

## Filing
- Agents may file issues for work found mid-task, bugs they hit, or follow-ups a person asked for. Each holds one change that can be completed and verified on its own, sits in the module that owns the area, and says what proves it done. File them as backlog so a person decides whether they happen.
- Search before filing; comment on an existing issue instead of duplicating it.

## People
- Mark an issue for a person (assignees ["human"] or a username) when it needs a decision, a credential or a check only they can make.
- Do not change priorities, modules or plans a person set; suggest the change in a comment.
- Design notes go in pages, linked from the issues they affect.
