Agents run this tracker: they file issues, keep them current and close them. People set direction and review what lands.

## Filing
- One issue, one change. Before filing, name the change that closes it and what proves it closed. If that takes two "and"s, file two issues.
- Search first. Comment on an existing issue instead of filing a duplicate.
- File each issue in the module that owns the area. If none fits, ask before creating a module.
- Work found mid-task gets its own issue, never only a line in a comment.

## Status
- backlog: not committed. todo: will happen. active: someone is on it now.
- Set active when you start; move it back to todo if you stop unfinished.
- A wait on another issue is a blocker link, not a status change.
- Close as done when the change is committed and the proof holds, with a comment saying what you checked and what you left out. Cancel what will not happen and say why.

## People
- Mark an issue for a person (assignees ["human"] or a username) when only they can do it: a decision, a credential, a purchase, a visual check. Leave issues marked for someone else alone.
- Ask before deleting issues or changing a priority a person set.

## Bigger work
- Work that needs a checklist is a plan or a module, with one issue per step.
- Design decisions and anything ongoing go in pages, linked from the issues they affect.
