# Issue collaboration panel

`empty_panel(cx, route, capabilities)` renders stable panel DOM while the issue request is pending. Once the route has an issue, call
`LificTopcoatIssueCollaboration.mount(root, { route, issue, capabilities })`.

The `issue` value is the API issue DTO. The route carries `{ issue_id, generation }`; capabilities carries independent `edit` and `comment` booleans. The route project identifier and public/private scope come from the enclosing issue-detail route. Mount fills in issue identity, relationships, waits, and role state before loading comments, activity, and attachment metadata. Calling `mount` again disposes the previous instance first. The returned controller also exposes `update(issue, capabilities)`, which updates issue-derived panels without replacing comment, relation, or wait drafts.

The controller exposes `setCapabilities(capabilities)` so a preserved route refresh can revoke or restore controls without remounting the panel or dropping drafts. Revoking comment permission makes any open edit read-only, disables its save/upload controls, cancels active comment uploads, and retains the draft for a later restore. Refreshes preserve the focused edit and its selection.

The panel dispatches `lific:issue-detail-intent` with `{ route, action }`. A panel mutation action has `{ type: 'mutate_panel', panel, operation, ...input }`; issue lifecycle actions have `{ type: 'delete' }` or `{ type: 'restore' }`. The route should send `lific:issue-detail-applied` with `{ route, panel, issue }` after a successful panel write, `lific:issue-detail-error` with `{ route, panel, operation, action, error }` after a failed write, and `lific:issue-detail-conflict` with `{ route, panel, operation, action, current }` for a stale write. Failed actions keep their form values and display the route error, so the user can retry. Successful actions clear only the draft that was submitted. Comment success refreshes the loaded comment window and activity; relationships and waits use the returned issue DTO, including omitted empty arrays. Refresh reconciles the loaded comment window by ID, fetching older pages as needed to replace stale rows or deletions. An explicit older-page action extends that window. Hash targets use `#comment-{id}` and walk back at most ten older pages.

Comment edit controls are restricted to the current author and are still checked by the server. Project-role capabilities gate composer, relation, wait, and delete controls. Mention candidates are project-scoped. Comments render through the Topcoat issue editor's shared Markdown renderer, with issue-reference links and mention styling. The issue attachment panel uses the shared uploader helper with an issue target; its mount survives background refreshes and is recreated after dispose/remount. Comment uploads use the shared helper without an entity target so viewers can upload without issue-maintainer permission; the comment create/edit API links referenced uploads to the comment when it reconciles the saved Markdown. Comment composer file input, paste, and drop insert attachment Markdown at the active selection and block submission until queued uploads finish. Audience changes, edit cancellation, permission revocation, and disposal clear queued files and ignore stale transfer completions. Issue attachment rows use shared kind detection, authenticated text/archive previews, image thumbnails and original links, and native audio/video controls. Comment deletion confirmation summarizes issue, attachment, and mention references before sending the mutation.
